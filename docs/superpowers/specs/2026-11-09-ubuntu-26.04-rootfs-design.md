# Ubuntu 26.04 rootfs support

Date: 2026-11-09
Status: Approved design

## Goal

Add Ubuntu 26.04 as a rootfs type with the same coverage as Ubuntu 24.04:
`amd64`, `arm64`, `arm32`, and `riscv64` builds, bootable with `run-qemu.sh`,
covered by the local test scripts and the multiarch CI workflow.

## Non-goals

- No refactor of the existing `type-ubuntu22.04` / `type-ubuntu24.04` scripts into a
  shared parameterized implementation.
- No kernel changes; the existing 6.1.22 images are reused.
- No change to Alpine or Amazon Linux behavior.

## Rootfs type

New `type-ubuntu26.04/`, mirroring `type-ubuntu24.04/`:

- `init-rootfs.sh`: unchanged; creates the 2 GiB ext4 image.
- `run-container.sh`: identical to 24.04 except the base image is `ubuntu:26.04`.
- `inside-container.sh`: same package list and configuration as 24.04:
  development tools, Qt6 dev files, Xorg/openbox, OpenSSH, udhcpc, serial console,
  and the `/mnt/linux-app` 9p automount. The rootfs copy uses `cp -a` instead of
  `tar`: Ubuntu 26.04's glibc uses `openat2`, which qemu-user 8.2.2 does not
  implement, so GNU tar fails with `Function not implemented` when building
  non-amd64 images.

Package availability was verified on packages.ubuntu.com for `resolute` (26.04 LTS):
`udhcpc` and `qt6-base-dev`, including all four target architectures, are present.
Any package renamed upstream will be adjusted during the build verification.

## Architecture mapping

`utils/arch.sh`: add `ubuntu26.04` to the `type_supports_arch` case list so
`ubuntu22.04`, `ubuntu24.04`, and `ubuntu26.04` accept every architecture.

`build-rootfs.sh`: update the unsupported-type error message to list
`ubuntu22.04, ubuntu24.04, ubuntu26.04` as the multi-arch types.

## Tests and CI

- `tests/test-arch.sh`: assert `type_supports_arch ubuntu26.04 arm64` and
  `... riscv64` succeed.
- `tests/test-all.sh`: add `do_test ubuntu26.04` to the amd64 suite.
- `tests/test-multiarch.sh`: accept an optional rootfs type argument, default
  `ubuntu24.04`. For the given type, build `arm64`, `arm32`, and `riscv64`, boot each
  with `tests/qemu-test.sh`, and rename the result to
  `rootfs_<type>_<arch>.ext4`.
- `.github/workflows/multiarch.yml`: run the multiarch job as a matrix over
  `ubuntu24.04` and `ubuntu26.04`, with `fail-fast: false`. The arm64 tools/networking
  test runs for each matrix entry against its produced image.

## Documentation

`README.md`:

- build examples include `ubuntu26.04`,
- multi-arch list mentions 26.04,
- the note about Ubuntu Qt6/Xorg packages includes 26.04.

## Error handling

No new error paths. Unknown type, unsupported architecture, missing binfmt handler,
missing kernel, and missing QEMU errors are unchanged.

## Verification

- `bash -n` on all added/modified shell scripts.
- `tests/test-arch.sh` (runs without root/Docker).
- Full verification requires root and Docker:
  `sudo ./build-rootfs.sh ubuntu26.04`, then `sudo ./tests/qemu-test.sh` on the
  resulting image for each architecture. The developer runs these manually because
  Docker access needs an interactive sudo password.

## Acceptance criteria

1. `sudo ./build-rootfs.sh ubuntu26.04 --arch arm64` produces an arm64
   `rootfs_arm64.ext4` that boots to `login:` under QEMU.
2. The same holds for `amd64`, `arm32`, and `riscv64`.
3. `./build-rootfs.sh ubuntu26.04 --arch sparc` and unknown types still fail with the
   existing actionable messages.
4. `tests/test-arch.sh` passes and asserts 26.04 multi-arch support.
5. CI matrix builds and boots 26.04 for all three emulated architectures, and runs the
   tools/networking test on the arm64 image.
